
# Component 1 — Personalized Physiological Recommendations using XAI

## 1. Overview

This component is part of the Hypertension Management Ecosystem. It explores hypertension-related risk patterns among older adults using physiological measurements, machine learning, Explainable AI (SHAP), and evidence-informed preventive recommendations.

The current prototype uses a trained Random Forest classifier. It accepts caregiver-provided patient inputs, generates a model output, explains the model's contribution patterns using SHAP, and returns general precautionary recommendations.

**Research limitation:** The current system is a research prototype. Its output is not a clinically validated absolute risk estimate for a defined future period and must not be used as a diagnosis or as a substitute for healthcare-professional assessment.

## 2. Current model

- Algorithm: Random Forest
- Training dataset: Linked NHANES I baseline and NHEFS follow-up records
- Initial eligible age range: 60–74 years at baseline
- Model inputs: Seven features
- Training workflow: `train_model1.py` and `compare_model1_algorithms.py`
- Selected model artifact: `models/model1_random_forest.joblib`

### Model inputs

| Feature | Description |
|---|---|
| `age` | Age at baseline |
| `sex_female` | Sex-coded input used by the original dataset |
| `sbp_baseline` | Baseline systolic blood pressure in mmHg |
| `dbp_baseline` | Baseline diastolic blood pressure in mmHg |
| `pulse_baseline` | Baseline pulse rate |
| `bmi` | Body mass index calculated from height and weight |
| `diabetes_history` | Reported baseline diabetes history |

BMI is calculated as weight in kilograms divided by height in metres squared.

## 3. Target definition

The prototype uses a provisional research-defined hypertension outcome by follow-up, constructed from historical baseline and follow-up records.

Candidate cases may include a reported hypertension diagnosis after baseline, elevated follow-up blood pressure using the historical study thresholds, or reported current hypertension medication use. Candidate controls require the specified baseline eligibility and follow-up conditions.

The outcome definition and the historical examination methods require further methodological review. Follow-up intervals vary between participants, so the current output must not be labelled as four-year, ten-year, or another fixed-horizon risk.

## 4. Model evaluation

The latest recorded comparison used 971 participants after excluding two participants with missing pulse-rate data.

### Random Forest results

| Metric | Result |
|---|---:|
| Five-fold cross-validation accuracy | 67.91% |
| Cross-validation ROC-AUC | 0.6913 |
| Held-out test accuracy | 66.67% |
| Held-out test ROC-AUC | 0.6746 |
| Held-out test recall | 26.87% |
| Held-out test Brier score | 0.2087 |

These results represent an initial experiment on a relatively small historical cohort. The observed differences between Logistic Regression, Random Forest, and XGBoost are modest.

The model requires further evaluation, probability-calibration assessment, external validation, and review of target construction before any clinical interpretation.

## 5. Explainable AI

SHAP is used to explain how the fitted model's inputs contribute to individual predictions.

The service returns:
- A contribution for each model feature.
- Whether the feature's contribution increases or decreases the model output relative to the SHAP baseline.
- A reconstruction check against the model's predicted probability.

SHAP describes the fitted model's behaviour. It does not establish causality, prove that a factor caused hypertension, or show that changing a factor will reduce risk by a particular percentage.

## 6. Recommendation layer

Recommendations are generated by a separate rule-based function and are informed by general preventive-health guidance.

Current examples include:
- Correct recording and repetition of blood-pressure measurements.
- Heart-healthy eating and avoiding excess sodium.
- Physical activity adapted to the resident's mobility and care plan.
- Individualized nutritional review when BMI may warrant further assessment.
- Continued clinician-directed diabetes care where relevant.

The recommendations are general precautionary information, not personalized medical prescriptions. Caregivers should follow the care home's clinical protocols and the resident's healthcare-professional guidance.

## 8. Running the service

The component requires Python with the dependencies specified in `ai/requirements.txt`, including pandas, NumPy, scikit-learn, joblib, SHAP, and Matplotlib.

From the repository root, the manual test can be run in the existing research environment using:

```bash
/d/NHANES_Hypertension/.venv/Scripts/python.exe ai/component1-physiological/tests/test_prediction_service.py
```

The test suite checks prediction generation, SHAP reconstruction, routing of existing-hypertension cases, age validation, required input validation, and blood-pressure cohort eligibility handling.

For a separate deployment environment, create and configure an appropriate Python environment using the repository's dependency list. Do not make the application depend on the local `D:/NHANES_Hypertension` path.

## 9. Limitations and future improvements

1. Review and finalize the historical incident-hypertension target definition.
2. Evaluate the model using a well-defined prediction horizon and suitable validation methods.
3. Assess probability calibration and obtain independent external validation.
4. Investigate additional compatible baseline features where coverage is sufficient.
5. Improve automated tests and input validation.
6. Integrate the service with the project backend and caregiver-facing interface.
7. Continue developing and evaluating the enhanced-input model separately.

The current prototype is intended for research demonstration, development, and methodological evaluation. It is not a clinically validated hypertension risk calculator.
